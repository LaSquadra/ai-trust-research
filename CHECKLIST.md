# Consequential-action checklist
Review aid, not certification.

| Check | Required answer |
|---|---|
| Accountability | Who sponsors, revokes and restores task authority? |
| Scope | Which receiver, operation, effect, quantity, duration and resources are allowed? |
| Identity | What actual OS/service principal and credential execute? Is the token intended for this receiver? |
| Mediation | Where is denial enforced, including direct programs, helpers and children? |
| Current authority | What policy version, expiry and revocation state apply at acceptance? |
| Outcome | Was the effect rejected, accepted or committed? What remains unknown? |
| Evidence | Which sources, interval and gaps support the claim? Is scan failure separate from no match? |
| Withdrawal | Which queues, sessions or derived credentials survive? Which effects cannot be reversed? |
| Recovery | Can restoration revive revoked authority or duplicate committed effects? |
| Proportionality | Can unrelated safe work continue? What latency, false blocking and sensitive retention are added? |
| Simplicity | What outcome improves over receiver-local controls alone? |
